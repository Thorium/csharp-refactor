# Changelog

The analyzers package, the `csharp-refactor` tool and both editor extensions share one version. The NuGet packages carry the notes of the last six versions; this file keeps every one.

## 0.1.11

A query expression over an `IQueryable` is an expression tree to the string, span, regex, culture and Select-fusion rules too. `from r in rows let l = "Row " + r.Name + " of " + r.Code` became `$"Row {r.Name} of {r.Code}"`, which in a tree is `string.Format`: EF6 refuses it anywhere and EF Core 10 in a `where`, where it evaluates only a final projection on the client; the lambda spelling was guarded, the query spelling not. The rules now share the one guard that knew both.

CR0173 joins a bare declaration right above the `if` into the conditional, F#'s `let v = if a then … else …`: `IEnumerable<int> xs; if (a) { xs = F(); } else { xs = G(); };` becomes `var xs = a ? F() : G();`. `var` only where both arms are of the declared type, so the local's type never changes, and the declared type otherwise (`long n = a ? 1 : 2;`); no rule turns an existing declaration into `var`. The declaration must be the statement right above, one variable, no initializer, no comment after its start, and the local unread in the condition and the arms; else the assignment form stands as before. The stray `;` after an `if`'s block goes with it.

CR0083 turns a System.Text.Json DTO's setters into `init`: its guard took any attribute with `Json` in the name for a serializer setting the property after construction, so `[JsonPropertyName]` kept every such DTO mutable, and CR0080 never saw it. System.Text.Json 8 and later sets an `init` property, by reflection and from the source generator alike (run before the change), so its property attributes - `[JsonPropertyName]`, `[JsonIgnore]`, `[JsonPropertyOrder]`, `[JsonInclude]`, `[JsonRequired]`, `[JsonNumberHandling]`, a property-level `[JsonConverter]` - no longer hold the setter. A compilation naming `JsonObjectCreationHandling` (Populate writes into what a property holds), a type-level `[JsonConverter]`, `[JsonExtensionData]` and Newtonsoft's attributes still do; the rest of the guard is unchanged, a property nothing in the code constructs included.

CR0173 takes `if`/`else if` chains too, left alone until now: every link returning (the last an `else`, or the `return` right after the chain), or assigning the one target with a closing `else`, is a ladder nesting on the else side only - `return n < 10 ? "small" : n < 100 ? "medium" : "large";`. One line when it fits; else an arm a line (`: c2 ? v2` one indent under the statement); else the condition and the value on lines of their own, `? v1` / `: c2` / `? v2` / `: v3;`, the layout of a long ladder written by hand. A declaration right above joins it as in the two-branch form. A chain comparing one scrutinee with `==` against constants stays CR0002's `switch`; a `throw`, a link of more than one statement or an assignment chain without its `else` keeps the `if`.

CR0185, new and off by default: a method returning `List<T>` or `IList<T>` whose every caller only reads the result returns `IReadOnlyList<T>`. Only the signature changes. A caller adding, sorting or reversing in place (`Reverse()` on the view would return a copy and change nothing), a method group, or an explicitly typed `List<T>` local keeps the method. A public method changes under `--api-changes` only.

CR0184, new: a private `static readonly T[]` table the code only reads is an `ImmutableArray<T>` - `["a", "b"]` from C# 12, `ImmutableArray.Create<T>(…)` before - since `readonly` fixes the field and not the elements. Every use must be a plain read: an element read, `.Length`, `foreach`, a LINQ call, or an `IEnumerable<T>`/`IReadOnlyList<T>`-typed argument. A `params` argument or a format (which would see one object where it saw the elements), a store, an array of mutable structs, or `Contains` (CR0023's set) keeps the array.

CR0183, new: a private `bool TryX(…, out T value)` whose callers only test it returns the value or null - `private Order? TryFind(string k)`, `return e;` for `value = e; return true;`, `return null;` for `return false;` - and its callers match it with `TryFind(k) is { } o` (`is not { } o` under a `!`, `is { }` for `out _`). A `return true` must hand over a value provably not null (a value type, the nullable flow state, a `new` or a literal; a `!` is a claim, not a proof), and every caller must use the call as a condition; a caller reading the value after the `if`, or on the false path, keeps the method as it is. Private methods of a type declared in one file only, for now.

CR0182, new: a `ContainsKey` check and an indexer read of the same key are one `TryGetValue` - `if (d.ContainsKey(k)) Use(d[k]);`, the guard-and-leave `if (!d.ContainsKey(k)) return 0; return d[k];` and `d.ContainsKey(k) ? d[k] : -1` alike, the F# side's FR0014. Nothing in the region may write the dictionary or the key, a dictionary field keeps the code where a method of the type naming the field is called between, and expression trees and query clauses keep it (`out var` is not allowed there). It yields to CA1854, which a .NET Framework build never runs.

CR0181, new: a `switch` statement whose every section returns a value, assigns the one target and breaks, or throws, is a switch expression - `case A: return "a"; case B: case C: return "bc"; default: throw …;` becomes `A => "a", B or C => "bc", _ => throw …`, the `default` moved last as `_`. A switch without `default` takes the `return` right after it as the `_` arm, and is left alone otherwise, since a switch expression matching nothing throws where the statement fell through. It yields to IDE0066. `csharp_refactor.CR0181.drop_throwing_default = true` leaves out a `default: throw …;` beside arms naming every member of a plain enum, so the compiler's CS8509 flags the member added later; an unnamed value then throws `SwitchExpressionException`, and CS8524 wants `none` for CS8509 to stay the signal.

From an adversarial review of these rules before release, each case a probe that ran the code before and after the fix, and each now a test. CR0182 matches `d[k]` by what the names mean (a `foreach` or lambda `k` was rewritten too), keeps reads inside lambdas and local functions, and - unless the dictionary is a local the member made and never hands on, and the key a constant or an uncaptured local - stands down on any call, construction, `await` or store that runs between the check and a read: a field key a method moved, a property dictionary a method wrote, an alias written, an owner reassigned all read the old value. Two checks in one member take distinct names. CR0183 no longer trusts the nullable flow state as proof of a true value (an array element, a dictionary value or an oblivious call is "not null" and null at run time), keeps a method beside another of its name (the new signature took the other's calls), and drops an out-parameter reset only at the top of the body (one in a `finally` ran after the value). CR0184 leaves `Aggregate` and `ElementAt` (ImmutableArray's own return default on an empty table and throw another exception, measured over 26 methods), slices, overloaded callees (a `ReadOnlySpan<T>` overload took the array) and callees that type-test the argument. CR0180 stands down wherever the compilation calls `FieldInfo.SetValue` (a `GetFields()` loader then threw FieldAccessException), and the write index sees nested deconstructions and parenthesised stores. CR0083 keeps a System.Text.Json setter whose property has an initializer or a constructor value: the source generator fills an `init` DTO by an object initializer, so a property missing from the JSON came back as default(T). CR0179 keeps a construction a `goto` returns over, one with a comment after it, and a one-line block too wide for one line. CR0173 and CR0181 assign only to a local, a parameter (not `ref`) or a field by name, through `this.` or a type: `o.F = c ? … : …` evaluates `o` before `c`, where the `if` evaluated it after, so a condition re-pointing `o` stored into the old object - the two-branch form had this since CR0173 began. CR0181 keeps a guarded label beside `default`, a switch through a user-defined conversion, and a switch sharing its lines. CR0173 leaves to CR0002 exactly the chains CR0002 takes, and keeps a chain with one value on every path. The query guard no longer covers the first `from`'s source, which runs locally.

`--api-changes` on the command line now opens every public shape, where it opened only the fixes that edit other files: the analyzer run never saw the flag, so a rule whose API fix stays in its own file (CR0080, CR0083, CR0180 on a public member of a library) reported nothing and fixed nothing, and only `csharp_refactor.api_changes = true` in `.editorconfig` reached it. The tool now lays the flag over the analyzers' options as that key, so such a fix is reported, suppressed, held and counted like any other.

A rule no longer stands down just because its Microsoft twin has a severity in `.editorconfig`: that proves no analyzer is loaded (a .NET Framework project never loads NetAnalyzers, a command-line build runs no IDE rule without `EnforceCodeStyleInBuild`), and none of them fixes anything unasked. `csharp_refactor.skip_microsoft_duplicates = true` says the Microsoft analyzers really run on the code, and restores the old behaviour: the rule skips what an enabled Microsoft twin already reports. `--create-config` writes the setting at its default.

CR0180, new: a static field nothing in the compilation writes is `static readonly`, and a literal one then goes on to CR0172's `const`. Nothing writing it means no assignment, `++`, `ref`/`out` argument, `ref` alias, `&`, static-constructor write, `nameof` or string literal of its name (a reflective write, which a readonly static refuses). A mutable struct keeps its field (readonly would copy it before a mutating call), and so do `volatile`, attributed and generic-owned fields. A public field is API; a private one yields to IDE0044 where that is on.

CR0179, new: a local set member by member straight after its construction folds into an object initializer - `var o = new Order(); o.Id = id; o.Total = total;` becomes `var o = new Order() { Id = id, Total = total };`, one member per line when it does not fit. The step before CR0083: the setters are then used only while constructing. Only the uninterrupted run right after the declaration folds, each member once, no value reading the local or declaring a variable, the local of the created type; F# twin FR0140, and it yields to IDE0017, which never runs on a .NET Framework build.


## 0.1.10

Two silent CR0032 sweep rewrites closed, each shown by a test that failed before the guard went in. A compound store's getter now counts where it runs: `acc.Sum += d[k]` reads `acc.Sum` before `d[k]`, so a getter that writes the dictionary through an alias keeps the loop, where it used to be timed with the setter at the end of the statement and the loop was rewritten. And the ToString a formatting runs is the nearest override up the base types: a derived type whose base overrides ToString to write the dictionary, formatted in an interpolation or a string `+`, keeps the loop too; only the type's own members were read before.

The tool's `--codes` and `--categories` now keep the rule modules outside the set from running at all, in the analyzer run and in the per-file fix step alike; they used to filter only the results, after every rule had run twice per file. A module is skipped by the codes it declares as `Code` literals, read off its compiled class, and a test holds every module to declaring each code it reports that way. The restriction lives in the run's own execution flow, so nothing running beside it - a test class in parallel with one driving the tool - loses a rule. A pass after the first re-analyses only the files the previous pass edited, kept or put back, and those holding a fix held to the next pass; a fix enabling one in an untouched file is found on the next run, a fix missed and never a wrong one applied. When the in-memory check puts files back, the pass total now counts the fixes of the files kept rather than the files. Restricted, the header says `1 of 131 rules`, and a later pass says how many files it re-analyses.

CR0023 leaves a literal too short for a set to pay, measured on .NET 10: `Contains` over an array or a List of a primitive or an enum runs a vectorised `IndexOf`, which a FrozenSet catches only at about 16 elements (a HashSet at about 8), while for strings, records and structs a FrozenSet wins from the first element and a HashSet from about 6. `csharp_refactor.CR0023.min_elements` overrides every case. CR0109 names a hoisted regex after the enclosing member before the pattern's words - `IsPostcode` gives `PostcodeRegex`, a taken name moves to the whole member name, then the words - and reads the words with their escapes cut out and their own capitals: `\bError\b` gave `BerrorRegex`.

The knobs the F# twins have, where C# has the shape. CR0040 offers a boundary drain's synchronous sibling - `x.LoadAsync(p).Result` becomes `x.Load(p)` where the method's own type declares an ordinary `Load` taking those arguments and returning the `.Result` value's type, never a task - in the editor, and a sweep applies it under `csharp_refactor.CR0040.sync_swap = true` (FR0049's `syncSwap`). CR0125 offers to comment a retired protocol out of a `|` of flags, operator and all, and a sweep does so under `csharp_refactor.CR0125.drop_legacy_protocols = true` (FR0065's). `csharp_refactor.CR0109.per_call = false` keeps only the regex hoists out of loops and per-element lambdas (FR0015's `perCall`). DESIGN.md had specified the first two; no rule read them. `--create-config` now writes every rule's knobs under its severity line at their defaults - one whose default is not a single value, CR0023's measured floor or a `wrap_column` falling back to the file's `max_line_length`, commented out - from a catalogue a test holds to the fallbacks the rules actually pass.

From an independent review of this version, each shown by a test that failed before. CR0040's swap binds the rewritten call where it stands and keeps it only when it reaches one of the synchronous siblings: a derived type's better overload (`Derived.Load(object)` for `d.Load(1)`) or a local function named like the sibling would take the call, compile, and run something else; and it stands down under a `catch (AggregateException)`, which `.Result` and `.Wait()` feed and the sibling would not. CR0125 retires a protocol only from the flags being switched on - the `|` chain the value of a plain `=` or an initializer - since inside `&= ~(Ssl3 | Tls11)` commenting one out re-enabled it, and inside `(p & (Tls | Tls11)) != 0` stopped detecting it. CR0109 never takes a name a base type holds - a field named like an inherited one hides it, and the inherited field's references silently rebind to the new pattern (CS0108 is only a warning) - nor the type's own name (CS0542), nor one visible at the site.


## 0.1.9

Silent sweep rewrites closed in five rules, each reproduced by a probe that runs the code before and after the fix - and every guard built the same way round: the fix by default, a note only where the analysis positively finds the edge, never for want of a proof. CR0032 (`foreach (var k in d.Keys) ... d[k]` to the pairs) keeps the loop only on what it sees write the dictionary before a lookup in the same iteration - since .NET Core 3.0 an overwrite or a Remove no longer breaks the enumeration, and the pair holds the value the iteration began with: the receiver handed on, reassigned or written, a method group of its writers taken, a store into another dictionary-typed value, a closure write, an `await` or `yield` between, and a call, getter, setter, constructor, operator, `Deconstruct` or enumerator whose visible body (three calls deep, a delegate's or lazy's through where it visibly came from, an event's through its visible handlers) touches a dictionary. A `Note(k)`, an `ILogger` call, a `Console.WriteLine`, a `ToString()` override, an event with no visible handler writing a dictionary: the fix, since nothing visible says otherwise. A computed-property receiver is accepted unless its visible getter constructs or counts. CR0166 keeps the catch only where the Parse argument is a shape that throws on its own - an element access or indexer (under a broad catch), a nested `Parse`/`Convert.To*`, `First`/`Single`/`ElementAt`/`Substring`/`Remove`/`Insert`, `Nullable.Value`, `Lazy`/`ThreadLocal.Value`, an `Exception` member on a non-sealed receiver, a user conversion, `checked` arithmetic - since that exception took the fallback too; a user getter or method, `string.Format`, `Trim`, `ToLower`, `textBox.Text`: the fix. CR0011's `Count(p) > 0`, `Where(p).Count() > 0` and `Count() > 0` to `Any` stand down only on a predicate with a shape known to throw or act - `Nullable.Value`, an indexer, a nested parse, division by a variable, `checked` arithmetic, `seen++`, `await` - or a source that visibly runs user code as it is enumerated: a call to a visible iterator (`yield`), a user collection whose visible `GetEnumerator` yields, `File.ReadLines`/`Directory.Enumerate*`, `Cast<T>()`, or LINQ over such a source; user methods and getters in the predicate, comparers and user element types are accepted, a null element or a user `Equals` throwing after the first match being the accepted residual. CR0022, CR0028 and CR0171 spell `Any`, `All`, `Where`, `Select` and `ToList` only where no extension of the repository's own would take the call. Accepted and documented: a BCL call that runs a user `ToString`, `CompareTo` or `GetHashCode`, a BCL callback, an `IEnumerable<T>` local holding a user iterator, a static member whose type initializer throws under a catch-all, and a null element after the first match.

The shared `callsOnlyCore` proof takes an auto-property's getter as the field read it is (never a virtual, abstract, interface or bodied one), so CR0020, CR0021, CR0022 and CR0028 now fire on conditions over auto-properties, and the rewrites execute as the loops did.

The visible-body proofs behind CR0032, CR0175, CR0011, CR0022 and CR0166 look further before standing down, and only on a visible writer. A property read runs its getter alone: `Name { get => _n; set => _n = value; }` read twice no longer held CR0175 (or CR0032, for a dictionary property) to the editor for the setter's `_n = value` nobody ran. A partial method's call is followed into its implementation part (`partial void Reset();` with `Reset() => _s = "x"` in the other file: a note). A delegate, lazy or sequence field or property is followed to every store in its type, not only the reading member: `_bump = Bump` or `_bump = k => _d[k] = 100` in a constructor or an `Init()`, a `Func<,>` property assigned in the constructor, `_h = (Action<string>?)Delegate.Combine(_h, new Action<string>(Bump))`, a function pointer's `&Bump`. CR0011 and CR0022 follow a user method or getter in the predicate three calls deep for a throwing shape or an effect on the world outside it (`Check(x)` with `calls++`, a `Substring` or an indexer inside; a pure `IsValid` still sweeps), follow the source to its visible origin (`var xs = Gen()`, a field the constructor fills with an iterator, `Items => Gen()`, `Items => objs.Cast<int>()`, a user method returning one) and take a user collection whose `GetEnumerator` hands back a hand-written enumerator writing its state as lazy; a parameter's `IEnumerable<T>` stays the accepted residual. CR0166 follows the argument's user methods and getters three deep for a throwing shape (`Get(s) => s.Substring(5)`, `First => _parts[0]`, `Raw => throw …`, a nested `int.Parse` under a `catch (FormatException)`: kept) — `Trim`, `string.Format`, `textBox.Text`, a plain user method still fix — and keeps `other.V = int.Parse(…)` where the flow state says `other` may be null (the catch absorbed the null reference; under `other!` the flow state is not-null and the fix stands). CR0175's getter proof reads `this._hits = 0` as one write, not a read beside it, takes a write-only field and a member of a fresh local as nothing the value depends on, and so sweeps `Name => Fmt(_s)` with `Fmt(s) { _hits = 0; return s; }`. Three visible edges the pass found are notes now: a getter that yields (`Items { get { Calls++; yield return 1; } }`), an iterator reached through `!`, `??`, `?:` or a `switch` arm (`_items!.Count(…)`, `(_items ?? Gen() : list`), an explicit `IEnumerator<int> IEnumerable<int>.GetEnumerator()` that yields, and CR0032 a function pointer through a cast in parentheses (`(delegate*<string, void>)(&Bump)`). CR0022 runs its speculative compile only for a candidate that will fix: a note-only loop paid a compile for nothing (Accumulation 16.6 s over 2,400 note-only flag loops).

A `char` constant as a divisor (`x % 'a'`) threw inside the new total-condition proof and, caught per rule, silently emptied every CR0011 and CR0022 hint of the file; the constant is now read by its type, and the file's hints survive `dynamic`, `default`, `sizeof`, `checked` and error types too. In a top-level program the escape proofs of CR0032 and CR0175 now read every top-level statement, not the one holding the loop: a neighbouring `var m = d;` lets the dictionary escape. CR0175 sees a deconstruction `(s, _) = ...`, a `ref` alias taken before the guard and a primary-constructor parameter written elsewhere in the type as writes of the receiver; CR0032 sees a writer taken as a method group (`Func<_, _> rm = d.Remove`) as an escape and an unbound call as a hazard, while a nested `foreach` over a BCL collection, `d.GetValueOrDefault(k)` and `CountBy` without a comparer no longer stand it down. ## 0.1.8

The speculative check behind most fixes binds only the members an edit touches when every edit sits inside member bodies: a body declares nothing another member binds against, so every other member's errors are the same before and after the edit, and comparing the touched members answers exactly as comparing the file did. A syntax error, a preprocessor directive, an edit outside a body, or a touched member not found again with every declaration around it at its shifted span keeps the whole-file check. One check on a 21k-line file went from 1.1 s to 14 ms, and a pass of every rule over that file from 1,298 s to 43 s (5.3k lines: 87 s to 6 s). CR0041/CR0043 find a method's call sites and subscriptions through a per-file index of the names each node spells instead of binding every node of every tree once per method; CR0023, CR0150 and CR0152 search a private field's uses inside its type's own declarations; CR0069 reads each tree's text once. Every suggestion and fix is unchanged - byte-identical on synthetic files and in the reports of real projects - and CSR_SPEC_VERIFY runs both checks side by side: they agreed on every one of the test suite's six thousand.

The tool's own code takes the notes FSharp.Refactor raises on it: the char overload of `EndsWith`, `IsNullOrWhiteSpace` for two trims compared with empty, one pass over a report's findings, the rule count read once per run, and a reference search that no longer copies its visited list per level. The sixteen deliberate fail-safes FR0055 notes carry their reason and an ignore-line, as FSharp.Refactor labels its own.
