# Changelog

The analyzers package, the `csharp-refactor` tool and both editor extensions share one version. The NuGet packages carry the notes of the last six versions; this file keeps every one.

## 0.1.9

Silent sweep rewrites closed in five rules, each reproduced by a probe that runs the code before and after the fix - and every guard built the same way round: the fix by default, a note only where the analysis positively finds the edge, never for want of a proof. CR0032 (`foreach (var k in d.Keys) ... d[k]` to the pairs) keeps the loop only on what it sees write the dictionary before a lookup in the same iteration - since .NET Core 3.0 an overwrite or a Remove no longer breaks the enumeration, and the pair holds the value the iteration began with: the receiver handed on, reassigned or written, a method group of its writers taken, a store into another dictionary-typed value, a closure write, an `await` or `yield` between, and a call, getter, setter, constructor, operator, `Deconstruct` or enumerator whose visible body (three calls deep, a delegate's or lazy's through where it visibly came from, an event's through its visible handlers) touches a dictionary. A `Note(k)`, an `ILogger` call, a `Console.WriteLine`, a `ToString()` override, an event with no visible handler writing a dictionary: the fix, since nothing visible says otherwise. A computed-property receiver is accepted unless its visible getter constructs or counts. CR0166 keeps the catch only where the Parse argument is a shape that throws on its own - an element access or indexer (under a broad catch), a nested `Parse`/`Convert.To*`, `First`/`Single`/`ElementAt`/`Substring`/`Remove`/`Insert`, `Nullable.Value`, `Lazy`/`ThreadLocal.Value`, an `Exception` member on a non-sealed receiver, a user conversion, `checked` arithmetic - since that exception took the fallback too; a user getter or method, `string.Format`, `Trim`, `ToLower`, `textBox.Text`: the fix. CR0011's `Count(p) > 0`, `Where(p).Count() > 0` and `Count() > 0` to `Any` stand down only on a predicate with a shape known to throw or act - `Nullable.Value`, an indexer, a nested parse, division by a variable, `checked` arithmetic, `seen++`, `await` - or a source that visibly runs user code as it is enumerated: a call to a visible iterator (`yield`), a user collection whose visible `GetEnumerator` yields, `File.ReadLines`/`Directory.Enumerate*`, `Cast<T>()`, or LINQ over such a source; user methods and getters in the predicate, comparers and user element types are accepted, a null element or a user `Equals` throwing after the first match being the accepted residual. CR0022's flag loop without a `break` takes the same tests. CR0175's length guard proves the cut where the guard and the cut read the same string: a visible write between them, a deconstruction, a `ref` alias, a variable a closure writes, a primary-constructor parameter written elsewhere in the type, an `await` or `yield`, a cut deferred into a lambda, and a call between them whose visible body (three deep) assigns the receiver hold it to the editor; any other call between, an interface call, a user operator or conversion whose body assigns nothing: the fix. A computed receiver is taken as stable unless its visible getter assigns, counts or constructs; the window under an `if` ends at the cut. CR0022, CR0028 and CR0171 spell `Any`, `All`, `Where`, `Select` and `ToList` only where no extension of the repository's own would take the call. Accepted and documented: a BCL call that runs a user `ToString`, `CompareTo` or `GetHashCode`, a BCL callback, an `IEnumerable<T>` local holding a user iterator, a static member whose type initializer throws under a catch-all, and a null element after the first match.

The shared `callsOnlyCore` proof takes an auto-property's getter as the field read it is (never a virtual, abstract, interface or bodied one), so CR0020, CR0021, CR0022 and CR0028 now fire on conditions over auto-properties, and the rewrites execute as the loops did.

A `char` constant as a divisor (`x % 'a'`) threw inside the new total-condition proof and, caught per rule, silently emptied every CR0011 and CR0022 hint of the file; the constant is now read by its type, and the file's hints survive `dynamic`, `default`, `sizeof`, `checked` and error types too. In a top-level program the escape proofs of CR0032 and CR0175 now read every top-level statement, not the one holding the loop: a neighbouring `var m = d;` lets the dictionary escape. CR0047 notes a top-level `lock` on a literal or a Type without the gate offer (no field can be declared among top-level statements) instead of throwing on the statement's missing parent. CR0175 sees a deconstruction `(s, _) = ...`, a `ref` alias taken before the guard and a primary-constructor parameter written elsewhere in the type as writes of the receiver; CR0032 sees a writer taken as a method group (`Func<_, _> rm = d.Remove`) as an escape and an unbound call as a hazard, while a nested `foreach` over a BCL collection, `d.GetValueOrDefault(k)` and `CountBy` without a comparer no longer stand it down. CollectionFixes compiled one match over every IOperation kind into a single method of a megabyte of IL, whose JIT cost about seven seconds once per process; split per kind, a one-loop file analyses in 0.66 s instead of 8.2 s, and CR0032's confinement verdict is computed once per symbol.


## 0.1.8

The speculative check behind most fixes binds only the members an edit touches when every edit sits inside member bodies: a body declares nothing another member binds against, so every other member's errors are the same before and after the edit, and comparing the touched members answers exactly as comparing the file did. A syntax error, a preprocessor directive, an edit outside a body, or a touched member not found again with every declaration around it at its shifted span keeps the whole-file check. One check on a 21k-line file went from 1.1 s to 14 ms, and a pass of every rule over that file from 1,298 s to 43 s (5.3k lines: 87 s to 6 s). CR0041/CR0043 find a method's call sites and subscriptions through a per-file index of the names each node spells instead of binding every node of every tree once per method; CR0023, CR0150 and CR0152 search a private field's uses inside its type's own declarations; CR0069 reads each tree's text once. Every suggestion and fix is unchanged - byte-identical on synthetic files and in the reports of real projects - and CSR_SPEC_VERIFY runs both checks side by side: they agreed on every one of the test suite's six thousand.

The tool's own code takes the notes FSharp.Refactor raises on it: the char overload of `EndsWith`, `IsNullOrWhiteSpace` for two trims compared with empty, one pass over a report's findings, the rule count read once per run, and a reference search that no longer copies its visited list per level. The sixteen deliberate fail-safes FR0055 notes carry their reason and an ignore-line, as FSharp.Refactor labels its own.


## 0.1.7

CR0166 puts its replacement in braces when the `try` is the unbraced body of an `if` with an `else`: `if (useSetting) try { port = int.Parse(s); } catch (Exception) { } else port = 9090;` became `if (useSetting) if (int.TryParse(s, out var parsed)) port = parsed; else port = 9090;`, the `else` changing hands - a bad setting fell back to 9090 and no setting at all kept 8080.


## 0.1.6

CR0054 leaves `Task.WhenAny`/`Task.WaitAny` of one task: `await t` and `t.Wait()` threw on a faulted task where they did not. CR0166 fixes a target that keeps its value on a bad input - `int port = 8080;`, a field the catch does not assign - through a fresh local: `if (int.TryParse(s, out var parsed)) port = parsed;`. CR0049 fixes a `Task`-valued check-then-store too: the store kept a failed task for good already, and CR0050 still notes it on the `GetOrAdd`. CR0164 fills a static whose factory may answer null with `Interlocked.CompareExchange(ref _x, Load(), null)`, where `EnsureInitialized` would throw. CR0178 moves a nullable integer, bool, enum or Guid column compared by `==`, `<`, `<=`, `>`, `>=` with a non-null value and under no `!` in a sweep: SQL and C# both drop the NULL row. CR0177 never hoists a division or remainder by an integral `-1` (`int.MinValue / -1` throws even unchecked), and takes a negated literal divisor otherwise.


## 0.1.5

A project that builds with `TreatWarningsAsErrors` (or a `WarningsAsErrors` list, or a `dotnet_diagnostic.X.severity = error`) no longer loses a whole run to one analyzer warning a fix raised. The in-memory check read the compiler's diagnostics only, so a fix that raised CA1859 passed it, the verification build failed, and every fix of the project was put back. Where the project escalates warnings, the tool now also runs the project's own analyzers whose diagnostics become errors (CA, IDE, third-party), and a document's fixes that raise one are held with the IDs and the rules named - `(A.cs: its fixes (CR0011) raised CA1860, an error under the project's warnings-as-errors - not applied)` - and not retried on the next pass. A verification build that still fails is narrowed first: the changed files its error lines name go back one round at a time until it builds, and only then does the whole project's set go back. CR0011 no longer rewrites `xs.Count() > 0` to `xs.Any()` on an array, a string or a collection with its own `Count`/`Length`: CA1829 asks for the property read there, and the `Any()` is CA1860's error under TreatWarningsAsErrors. CR0040 reads a drain behind a completion test in the same condition as a read, not a block - `winner == work && work.IsCompleted && work.Result`, the right operand of `&&` running only when the probe held - and the task compared equal to the winner of `await Task.WhenAny(…, t, …)` as complete; `!t.IsCompleted` no longer counts as a completion test in its then-branch. CR0178 (performance, fix): a query copied before `Where` or `Select` runs them in the query - `db.Orders.ToList().Where(o => o.Total > 0).Select(o => o.Id)` becomes `db.Orders.Where(o => o.Total > 0).Select(o => o.Id).ToList()` - for column comparisons and column projections only; a sweep moves the ones SQL answers as C# does (integers, bool, enums, Guid) and the editor offers the string, decimal, date and nullable ones. F# twin: FR0174.

A review of the whole analyzer and tool code, every finding reproduced by a failing test before its guard went in. CR0178 moves a copy only past value columns (a navigation property is null in memory without an `Include` where the query joins it) and only where the chain's new static type (`List<T>` for `IEnumerable<T>`) binds as before - elsewhere the editor offers it. Silent rewrites closed: CR0108 parenthesises a compound subject (`Regex.Replace(s ?? "", …)` became `s ?? "".Replace(…)`); CR0126 keeps an object initializer (the key and IV of `new AesManaged { Key = k }` were dropped); CR0029 stands down when the second lambda writes its parameter; CR0102 only in a plain string (a FormattableString or a provider's handler formats the hole its own way); CR0173/CR0002 only where every arm converts as before (`object M() => a ? 1 : 2.0` boxed a double); CR0040/CR0041 hold under a handler that reads the wrapper; CR0043 needs a caller and an open surface; CR0150, CR0149 and CR0151 read the other files' uses; CR0166 keeps a broad catch whose argument can throw; CR0015 keeps a worklist field a called method appends to; CR0082 holds a tuple compared by reference; CR0020 keeps the copy before a short-circuiting consumer over a generator; CR0005 keeps comments; CR0065 keeps a condition that can throw as a note; CR0090 skips parameter defaults; and CR0006, CR0155, CR0089, CR0109, CR0033, CR0154, CR0152, CR0081. Crashes: `Text.isTestFile` on a C# 12 tuple alias, CR0107/CR0109 on a `NotSupportedException` pattern, the MCP server on malformed requests (unknown codes and categories now answer an error, as on the command line). The tool: a failed verification build puts back whole fix units, never half of a reshaped method and its callers, and a project folder no longer matches its `FooBar` sibling. A `<Sdk Name="…"/>` project is SDK-style. CR0063 leaves a `ref struct`'s public `Dispose` (C# `using` takes the pattern without `IDisposable`), and CR0168 notes `(int)MathF.Ceiling(items / pageSize)` - only `Floor` and `Truncate` agree with the integer division's truncation; the page count rounded up after truncating was the bug. Every rule now has a dedicated guard test beside its happy path (the C# 15 union rules CR0156/CR0158 wait for a Roslyn with unions for theirs).


## 0.1.4

CR0146 documents every member of an enum, not only the last: the note trailing `Transient,` sits after the comma, and a comma separating two members belongs to the enum's list rather than to the member before it, so the member's own trivia never held the note. The patterns the rules match with are built once at module level instead of being looked up in the static pattern cache on every call — CR0109's name for a hoisted regex, CR0146's and the switch-stub rule's reading of a comment as code, the exception-message word split and its count of a literal across the tree, the solution and legacy-project readers, and the framework-moniker parse each ran one per candidate; `LoopInvariant` climbs to the enclosing loop through a struct-returning active pattern rather than a guard. The F# compiler's warnings are back to none, and one of them was a name a consumer sees: `Guards.checked` is `Guards.verified`, `checked` being reserved. The type tests that could not fail are gone with it — `GetDeclaredSymbol` on a parameter, a method or a property already hands back the narrow symbol, so `:? IParameterSymbol` never chose anything and the null check it stood in front of is what the code meant — as are two casts to a type the expression already had and an `@` in a test's name. `StringClaimTests` checks its premises again: a sweep had rewritten the `Substring`, `ToCharArray` and parse sides of three claims into the span and string shapes they are compared against, leaving `x = x` — a property that passes on every input and stands behind CR0174 and CR0176 saying nothing.

## 0.1.2

The Visual Studio extension gained the Tools > CSharp.Refactor menu the VS Code extension always had: run the tool on the open solution (apply or dry run, with or without `--api-changes`), review the advisory notes as a page, write a SARIF report, create or open the `.editorconfig` block, status and about — a registered package (`Commands.fs`, net48) beside the analyzer asset, its output in a CSharp.Refactor pane, open documents saved before a run. The tool ends a run with its timing — load, compile and analysis wall clock, the rule modules summed across threads and the five slowest, the cross-file index under its own name and out of the rules' figures (the first rule to ask used to carry its build, and every rule waiting behind it the wait). What the record showed on a 270-file project, and what changed: the index is built per tree in parallel (6.0 s → 0.9 s) and only asked for by a file with a candidate; CR0145 bound every `a.b` of a file twice (a startup file of service-registration chains: a quarter of a second for nothing) and now binds a chain only when its root is spelled like a namespace the compilation knows; CR0023 walked every tree of the compilation per literal table and now only the trees that can see the field; CR0083, CR0145 and CR0149 re-bound the file once per candidate (a DTO file of forty setters: forty forks) and now once per file, `Guards.speculativeCheckEach`, falling back to one by one only when the batch carries an error. Analysis of that project: 24 s → 18 s wall, 159 s → 68 s of rule time. An MSBuild warning of a project that loaded (a NuGet NU1510, say) is printed dim, not red: Roslyn's loader hands every MSBuild message over as a failure, and only a project that did not come back is one. CR0108 rewrites `Regex.Matches(s, "lit").Count` to `s.AsSpan().Count("lit")` (.NET 8) and `Regex.Split(s, "lit")` to `s.Split("lit")`, and CR0109 never hoists a plain-text pattern into a generated regex — the regex over plain text is the thing to lose, not to cement. `benchmarks/PerfClaims` now measures every performance rule (16 pairs added, CR0045 and CR0054 excused with a reason) and a test keeps the accounting: a performance rule without a pair or a reason fails the suite. Two rules: CR0172 makes a local initialised with a constant and never written a `const` (`var schema = "app"` → `const string schema = "app"`; a hole filled from it is then text to CR0120), and a `static readonly` field of a constant too — FR0130's `[<Literal>]`, so a public or protected field waits for `--api-changes` (a `const` is a different member to a consumer already compiled); CR0173 hoists a `return` or an assignment every branch of an `if` performs into one conditional (`if (a) return "1"; else return "2";` → `return a ? "1" : "2";`) when the result is one line within the wrap column, standing down for the bool-literal spellings that are CR0001's and yielding to IDE0046/IDE0045. Three more, the F# side's FR0106, FR0166 and FR0167 ported: CR0174 hands a `Substring` (or a C# 8 range) to a consumer whose `ReadOnlySpan<char>` overload is the same operation as `AsSpan` — `Parse`/`TryParse`, `StringBuilder.Append`, `TextWriter.Write`/`WriteLine`, `string.Concat`; the comparison methods stay out, their span twins being ordinal where the string ones are culture-sensitive; CR0175 turns a prefix or suffix cut out to be compared with a literal into the ordinal `StartsWith`/`EndsWith`, only under a length guard on the same string (a short string threw where the rewrite answers false); CR0176 enumerates the string a `foreach` read through `ToCharArray()` — the `foreach` only, since LINQ over a string measured nine times slower than over the array. Each pair is in PerfClaims, and `StringClaimTests` checks the equivalences on random strings, non-ASCII and the Turkish `İ` included.

## 0.1.1

The package icon (shared with FSharp.Refactor) on both NuGet packages, the VSIX and the VS Code extension. A legacy project's or a script's file that is not UTF-8 came back with U+FFFD for every non-ASCII byte, and on Linux and macOS the system code page is UTF-8, so the CI tests for Windows-1252 failed there: both loaders decode as MSBuildWorkspace does (a byte order mark, else strict UTF-8, else the system page — Windows-1252 where the platform has none) and the MSBuild load re-reads any document Roslyn's loader replaced bytes in, so a file goes back as it came in on every platform. The property suite reaches 121 of the 124 rules and tries every fix under the conventions of real files (regions, directives and comments inside members, CRLF, tabs, pragmas) and at every language version from C# 7.3 up; the example suite tries the conditions any rule may meet (shadowing, reflection and `nameof`, expression trees, `dynamic`, `unsafe`, partial types across files, interface and override members, generated files, a framework lacking a type). What that found before the release: CR0084 offered `readonly` where a method wrote the field; CR0109 hoisted a pattern the engine rejects into a generated regex; CR0047 spelled `System.Threading.Lock` and `new()` into files below C# 13 and C# 9; CR0009 folded an `or` pattern below C# 9 and stacked labels with a bare LF in a CRLF file; CR0029 fused Selects inside an expression tree; CR0153 missed a partial type's other file and a field reached by reflection; the tool rewrote files carrying an `<auto-generated>` header. The MCP server (`--mcp`) is now under test end to end.
